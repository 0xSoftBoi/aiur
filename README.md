# aiur

Stratospheric observation, built the unglamorous way.

Aiur is an engineering project for small lighter-than-air packages that
climb into the stratosphere, observe the ground from there, report what
they see, and come back. No aircraft, no dock, no deployable payload: pure
observation.

## Current milestone: STRATO-P0

We are deliberately **not** starting with a persistent float platform.

STRATO-P0 exists to answer the program's highest-risk question:

> Can a small, cheap, legally exempt package climb into the stratosphere,
> observe the ground with a stated resolution, report, and come back —
> twice, in the same configuration?

The first flight article is a latex sounding balloon under a sub-kilogram
imaging package with two independent trackers, a drop-tested parachute,
and a flight termination that works with the payload computer off.

### P0 scope

- helium lift only;
- one payload package, ≤ 1.0 kg allocation, 4 lb hard ceiling;
- sounding regime: climb at ~4.5 m/s, burst near 34 km, ~30 min above 20 km;
- geotagged observation frames above 20 km, the lowest altitude that is
  stratospheric at every latitude;
- cold soak, tethered ascent, then two free flights of one configuration;
- airspace coordination on file before every release;
- no float, no station-keeping, no propulsion until the sounding flight is repeatable.

### Explicit non-goals

P0 does **not** attempt a fixed-volume float envelope, hydrogen lift,
propulsion, real-time video, a deployable payload of any kind, or any
aircraft. Float is STRATO-P1 and is gated on P0, not scheduled after it.

## Executable model

The physics the article is designed against is one dependency-free module:
a 1976 standard atmosphere, lifting-gas density, the constant-gas-mass
sounding regime (launch volume, ascent rate, burst altitude, time aloft),
the fixed-volume float regime (envelope sizing, float altitude), parachute
descent, observation geometry (horizon, visible cap, ground sample
distance, swath), battery and day/night power budgets, and the regulatory
exemption thresholds the package is kept under.

```
python -m aiur.strato
```

Every number quoted in [docs/prototype-strato-p0.md](docs/prototype-strato-p0.md)
is regenerated by that command, and [tests/test_strato.py](tests/test_strato.py)
anchors the atmosphere against the standard's tables. CI runs both on
every push.

## The prototype

The Rev-A flight package is a buildable article, not a diagram:

- **Hardware packet** in [hardware/strato/](hardware/strato/README.md):
  a [BOM](hardware/strato/bom.csv) that marks every figure as published or
  allocated, a [generated enclosure cut sheet and section](hardware/strato/cad/generated/),
  the [S0-A bench and cold-chamber test card](hardware/strato/s0a-test-card.md),
  the [S0-B/S0-C launch checklist](hardware/strato/launch-checklist.md),
  and the log and manifest templates the reducer reads.
- **Flight supervisor** in [aiur/flight_supervisor.py](aiur/flight_supervisor.py):
  the package's state machine, with termination latched and an independent
  hardware timer modelled separately so the "computer froze at −55 °C" case
  is tested, not hoped about.
- **Simulated flights** in [aiur/strato_sim.py](aiur/strato_sim.py): the
  real supervisor stepped through the ascent model with seeded gusts and
  the hazard log's fault menu (GNSS lost, telemetry blackout, float-off,
  frozen computer, ground termination).
- **Evidence reducer** in [aiur/s0_evidence.py](aiur/s0_evidence.py):
  flight logs and manifests in, S0-A and S0-C gate verdicts out, with
  simulated evidence labelled as such and never closing a requirement.

```
python -m aiur.strato_sim --scenario nominal --flights 2 --out /tmp/s0
python -m aiur.s0_evidence flight --log /tmp/s0/nominal-1-flight-log.csv --manifest /tmp/s0/nominal-1-flight-manifest.json \
                                   --log /tmp/s0/nominal-2-flight-log.csv --manifest /tmp/s0/nominal-2-flight-manifest.json \
                                   --trials /tmp/s0/sim-termination-trials.csv
```

CI runs that chain on every push, so the S0-C gate is exercised end to end
before a balloon is bought.

## Gates, requirements, hazards

The evidence machinery built for the carrier program is kept and
re-pointed:

- **Gate ladder** `S0-A` (bench and cold chamber) → `S0-B` (tethered
  ascent) → `S0-C` (stratospheric sounding), executable in
  [aiur/loop_graph.py](aiur/loop_graph.py) with a new *free flight* stage
  that can only be entered from a passed tethered gate.
- **Requirement closure matrix** `S0-*` in
  [aiur/requirements.py](aiur/requirements.py) — `python -m aiur.requirements`.
- **Hazard log** `HAZ-013`…`HAZ-017` — the package descending onto a
  third party, conflict with manned aircraft, loss of the package,
  cold-induced power loss, and launch handling — in
  [aiur/hazards.py](aiur/hazards.py), with the same rule as before: no
  residual above LOW is accepted anonymously.

Program contract: [docs/engineering-loop.md](docs/engineering-loop.md).

## Carrier lineage (parked)

Aiur began as a lighter-than-air carrier that would launch and recover
autonomous aircraft onto a belly dock. That work — the CARRIER-P0
specification, the dock mechanism and its Rev-A/Rev-B CAD, the fail-safe
dock controller, the digital twin and its SIL gates, the fleet-throughput
and capture-architecture studies — is retained in this repository as a
parked lineage. Its gates stay in the loop graph and its tests stay green,
but it is not the funded article and nothing on the STRATO-P0 critical path
depends on it.

## Design rule

Every claimed capability must resolve to one of:

1. a measured requirement,
2. an executable model/test,
3. a cited component specification, or
4. an explicitly labeled engineering target.

Concept art is not evidence. A picture from altitude with no position tag
is concept art.
